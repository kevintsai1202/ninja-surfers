# Ninja Surfers 忍者跑酷：設計文件

致敬《地鐵跑酷》（Subway Surfers）的 3D 無盡跑酷網頁遊戲，換成火影忍者風格。個人非商業作品，部署在 GitHub Pages（kevintsai1202/ninja-surfers）。

## 1.1 美術方向（2026-10-03 追加：精細度比照地鐵跑酷）

使用者要求角色與周圍場景都要有地鐵跑酷等級的精細度。做法：

- 渲染：風格化 PBR（`MeshStandardMaterial`，高粗糙度、非金屬，金屬零件例外）＋程式產生的環境光（RoomEnvironment）＋太陽方向光柔和陰影（PCFSoft，陰影範圍跟著玩家）＋ACES tone mapping。角色可加極細的深棕描邊保留動畫感（給使用者看有／無兩版再決定）。
- 地平線下彎（地鐵跑酷招牌的 curved world）：全域改寫 `project_vertex`，世界座標越往前越往下彎；遠景材質用 `NO_CURVE` 例外。世界往玩家移動（場景 group 的 z = 跑的距離），角色與鏡頭留在原點附近，所以彎曲原點固定。
- 程式材質（canvas 產生、可重複貼）：木紋、木板、屋瓦、灰泥牆、石磚、道碴碎石、樹皮、苔蘚、草地、岩壁、布料等，含凹凸貼圖。
- 角色細節：夾克版型（高領、拉鍊與拉鍊頭、肩膀漩渦臂章、袖口反摺）、有拇指的手掌、涼鞋帶與腳趾、綁腿、忍具袋、曲面護額（倒角金屬片＋刻紋凹凸）、分層彎曲髮束。
- 場景道具密度比照地鐵跑酷：
  - 木葉村：道碴＋枕木＋鋼軌的三條軌道；木造列車（車窗、車門、轉向架與車輪、連結器、屋頂、車身色帶與塗鴉）；和風商店街（瓦屋頂、暖簾、招牌、燈籠、木格窗、屋頂水塔）、電線桿與電線、圍牆、鳥居、樹；遠景刻臉岩壁與山。
  - 死亡森林：運木軌道、巨樹（板根、樹皮、苔蘚）、蕨類與灌木、垂藤、蘑菇、林間光束、飄落葉片。
  - 終末之谷：水面（波紋、反光、浪花）、層理岩壁、碎石、兩座對望的巨大石像與瀑布（流動貼圖）、霧氣。
- 效能：每段場景依材質合併網格；只有近處主要物件投影；像素比上限 2（手機 1.5）。
- 三個場景各自是一個模組（`src/render/biomes/<id>/`），介面相同（`BiomeKit`：建一段場景、建障礙外觀、遠景、入口地標、每幀動畫），有 `?scene=<id>` 預覽模式可截圖驗收。

## 2. 玩法

- 三線道自動往前跑，越跑越快；左右換線、上跳、下翻滾（空中按下＝急降落地後翻滾）。
- 正面撞上障礙＝倒地被抓（遊戲結束）；換線時側面擦撞＝踉蹌、彈回原線，追捕者貼近；危險期內再踉蹌一次就被抓。
- 列車可以從斜坡跑上車頂，在車頂奔跑；車頂跑完會落回地面。
- 開場：忍者在刻臉岩壁上塗鴉被發現（致敬第一集），追捕者喊「站住！」，開始逃。

| movingTrain 迎面列車 | 同上，接近時迎面駛來 | 換線 | 木造列車（亮燈冒煙） | 運木台車 | 漂流巨木 |

碰撞規則（每個模擬步）：
1. 先算落腳高度：與玩家水平範圍重疊、頂面不高於「腳底＋0.35」的平台（車頂、斜坡面、擋牆頂）取最高者。
2. 玩家判定盒仍與實體重疊時：上一步已經橫向重疊、這一步才在 z 方向進入 → 正面撞（死亡，有卷軸滑板則替身術抵銷）；上一步沒有橫向重疊（換線造成）→ 側撞踉蹌、彈回原線。

### 2.4 追捕者

- 狀態：`gap`（在玩家身後幾公尺）、`danger`（危險期剩餘秒數）。
- 開場 3 秒貼在身後，之後退出畫面。踉蹌時貼近（gap 2.5 m），危險期內再踉蹌一次＝被抓。
- 伊魯卡老師：危險期 8 秒。1800 m 起換暗部：危險期 10 秒、貼近更快，顯示「暗部出動！」。
- 兩者都帶一隻忍犬。被抓時伊魯卡揪耳朵，暗部壓制。

### 2.5 計分與存檔

- 分數＝跑的距離 × 倍率（影分身時 ×2）。兩另外計，存進總額。
- 存檔（localStorage，讀寫包 try/catch，帶 `schemaVersion`）：最高分、兩總額、卷軸滑板數（初始 2）、兵糧丸數（初始 1）、靜音、是否看過教學。

## 5. 架構

純 Three.js（不用 React），UI 用 DOM 疊加層，文字一律繁體中文。

```
src/
  config.ts            所有數值常數
  sim/                 純 TS 模擬，不依賴 three／DOM，可在 Node 測試
    rng.ts             mulberry32 種子亂數
    types.ts           實體與狀態型別
    speed.ts           速度曲線
    player.ts          換線、跳、滾、重力、落腳高度
    collision.ts       判定盒、正面撞／側撞／落地
    patterns.ts        關卡圖樣模板
    track.ts           依速度排間距、生成與回收實體
    powerups.ts        道具效果與計時、秘傳卷軸獎勵
    chaser.ts          追捕者狀態與身分切換
    biome.ts           場景輪替與轉場比例
    run.ts             整局 step(state, input, dt) → 事件
    autopilot.ts       自動駕駛（展示模式、公平性測試）
    save.ts            存檔（純函式、不可變更新）
  render/              three 畫面：卡通材質與描邊、角色、場景、障礙、兩、特效、鏡頭
  audio/               Web Audio 合成的和風背景音樂與音效
  input/               鍵盤、滑動手勢（判定邏輯是純函式）
  ui/                  HUD、標題、暫停、結算
  game.ts              遊戲流程：標題 → 開場 → 奔跑 → 倒地 → 結算／復活
```

- 模擬每幀切成數個 ≤ 1/120 秒的子步，任何更新率都順；測試用固定 dt。
- 模擬只產生資料與事件（撿到兩、跳、撞、踉蹌、換場景、換追捕者…），畫面、音效、UI 依事件反應。
- 畫面以 id 對應模擬實體，物件池重複使用；兩用 InstancedMesh；場景道具每段合併成少數幾個網格（頂點色＋卡通材質），控制 draw call 給手機用。
- 角色由多個部件組成的關節階層，動畫全部程式產生（忍者跑、跳、滾、換線傾身、踉蹌、倒地、衝浪、騎蛤蟆）。
- 除錯鉤子 `window.__game`：讀狀態、指定種子、跳到指定距離、給道具、強制撞擊，供 e2e 與截圖驗收。

## 6. 測試

- 單元測試（Vitest）：模擬層全部先寫測試（物理、碰撞、道具、追捕者、場景、生成器不變量、存檔、手勢判定）。
- 公平性：自動駕駛在多個種子下跑到 3000 m 不死，證明生成器沒有排出無解的組合。

## 9. 第二版：iPhone 音效修正與新招式（2026-10-04 使用者確認）

### 9.1 iPhone 沒聲音

- 根因方向：iPhone 的響鈴／靜音鍵開在靜音時，網頁的 Web Audio 會被一起靜音（Safari 預設把 Web Audio 歸在 ambient 類）；另外現有 `unlock()` 不管 `resume()` 成不成功都標成已解鎖，之後不再重試。
- 修法：`navigator.audioSession.type = 'playback'`（iOS 16.4+）；舊版 iOS 在解鎖手勢裡播一段無聲的 `<audio>` 迴圈，把音訊工作階段切到媒體播放；每次使用者手勢（touchend／click／keydown）都檢查 `AudioContext.state`，不是 running 就再 resume；切回分頁時也重試（iOS 的 interrupted 狀態）。
- 驗證：Chromium 手機模擬、不開自動播放放寬的 e2e（點「開始」後量得到聲音）；靜音鍵的部分只能請使用者在 iPhone 上確認。

- 被抓（危險期內第二次踉蹌）只有替身木頭能救；卷軸滑板只擋正面撞擊、影分身只擋小障礙，都不救被抓。
